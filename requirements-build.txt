# 构建依赖锁定（release-windows 专用）：本组版本 = 与 CI 的 Python 3.11 兼容，
# 且【实测能打出可启动的 EXE】（Release v1.4.80 起由本文件构建，窗口真机验证通过）。
#
# ⚠️⚠️ 两条血泪纪律，改任何一行前必读 ⚠️⚠️
#
# 1) 【版本必须 3.11 可装】v1.4.75 首次锁定把 numpy 钉成 2.5.4 —— 它
#    requires_python >=3.12，而 CI 用 3.11 → v1.4.80 发版时 release-windows
#    直接失败在安装步骤（pip: No matching distribution found for numpy==2.5.4）。
#    改版本前先 `pip install --dry-run` 或查 PyPI requires_python 确认 3.11 可装。
#
# 2) 【绝不能加 librosa（等带原生重依赖的包）】v1.4.80 曾把它当「漏掉的运行时
#    依赖」补进来，结果打出**开不了窗口**的 EXE：librosa 拖进 numba + llvmlite +
#    sklearn + soxr，其原生 DLL（VCOMP140.DLL、llvmlite.libs）破坏 pythonnet 的
#    CLR 加载 → `Failed to resolve Python.Runtime.Loader.Initialize`。
#    已用对照实验证实：把（能启动的）v1.4.75 包塞入这些目录即立刻复现同样错误；
#    反之 v1.4.75 CI 清单不含 librosa 时的 EXE 能正常起窗口。
#    主程序对 librosa 是惰性 import + try/except 降级（强卡点/节拍同步），
#    缺了只退化为「无自动卡点」，不崩——比 EXE 打不开好得多。
#    加任何新依赖前，先看它会不会拖进原生库（numba/llvmlite/sklearn/soxr/opencv…）。
#    **改动后必须重新打 tag + 真机验证窗口能开**（跑 dist\FrameCut\FrameCut.exe，
#    窗口出现 / 8765 监听才算过；--selftest 只验重依赖导入，不验窗口层）。
#
# 本清单 = requirements.txt 去掉 torch/torchaudio（桌面 EXE 不打包 torch：
# CosyVoice/ChatTTS/IndexTTS2/Qwen3-TTS 都走各自的独立 venv 子进程），
# 再去掉 librosa（原生依赖破坏 CLR 加载，见上）。yt-dlp 是纯 Python 包
# （B 站下载功能），不引入原生重依赖，保留。
# CI 的 pytest 回归（ci.yml）不受影响，仍走 requirements.txt + requirements-dev.txt。
