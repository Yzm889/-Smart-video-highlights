# 一帧成片 · FrameCut

[English](README.en.md) · 当前版本 **v1.4.75**

本地运行的 AI 影视解说 / 直播切片 / 短视频剪辑工具。给它一部片子和一段剧情（或你自己写的稿子），它会**写解说词、逐句配音、按内容挑画面、配音念完再切镜头**，最后出成片；给它一场直播录像，它会**自动找出高光时刻、在精剪时间轴上自由调整、切成横竖屏短视频**，可直接发平台。

全程本地推理：不花 API 费用、素材不上传、断网可用。也内置强卡点、素材库、B 站下载、自动封面等短视频工具。

## 功能特性

### 影视解说（主线）

| 能力 | 说明 |
|---|---|
| **剧情驱动剪辑** | 先出完整解说稿，再按每句需要的画面时长从原片挑镜头。解说没提到的画面自然被剪掉，成片明显短于原片 |
| **整稿生成** | 开场钩子 / 因果推进 / 结尾升华，一次写完整篇，不是把画面描述拼起来 |
| **自带稿子** | 粘贴你写好的稿子，工具只负责「按稿子找画面 + 逐句配音 + 烧字幕」，一个字都不改你的稿 |
| **配音念完再切** | 画面按真实配音时长补齐，每句留 0.5 秒气口（可调），不再出现「话没说完就切镜头」 |
| **引用台词让位** | 稿子里引用台词的句子（`弗兰克回了一句：“我不想交朋友。”`）不念稿，直接切原片那句台词的镜头 + 原声 + 台词字幕 |
| **译名自动归一** | 稿子里的人名自动对齐到台词字幕的叫法（稿子写「柯蒂斯」、字幕写「科特」→ 自动统一），根治「解说讲 A 的对话、画面放 B 的对话」 |
| **留白标记** | 某句只写「（留白）」，这句就不配音、不出字幕，原声全量，把话筒交回给画面 |
| **两步走确认** | 先生成全部配音供试听，确认后再合成视频；不满意可单段重配，不用整片重跑 |
| **预览即成片** | 配音完成后自动合成预览，预览区直接看成片，不是源片 |
| **导出前确认** | 合成前弹确认框：段数、成片时长、最长最短段、音量范围、告警清单一目了然 |
| **手动调整时间轴** | PR 式编辑器：拖拽片段、改入点出点、删除、插入 B-roll、调原声/解说音量、撤销重做 |

### 字幕导入（解说与切片通用）

- **编码自适应**：UTF-8 / GBK / GB18030 / UTF-16 自动识别——字幕站下载的官方字幕直接拖进来就行
- **格式全兼容**：SRT / VTT / ASS / SSA / 笔记式时间轴（`[MM:SS] 台词`）
- **大块体检**：导入时检测「多条字幕被合并成大块」并警告（台词定位精度问题）
- **人名译名提醒**：导入前提醒稿子与字幕的人名译名要对齐（画面配错的常见原因）

### 配音

| 引擎 | 说明 |
|---|---|
| **IndexTTS2**（默认） | 零样本克隆。用一条固定参考音，整片同一把嗓子；支持 8 维情感控制 |
| **Qwen3-TTS · VoiceDesign** | 用文字描述造音色。默认只用来「铸」一条参考音，也作为克隆失败时的兜底 |
| 旧引擎（可选） | edge-tts / sherpa-onnx / 系统 SAPI / CosyVoice / ChatTTS，仍可在设置里显式选用 |

语速统一由 `rate` 控制（默认 1.12×，ffmpeg atempo 保音高），试听与成片同参。

### 画面理解四档

「没台词的精彩镜头」（打戏、对视、吻戏）会不会被剪掉，取决于画面理解这一段的档位。解说卡里可直接选：

| 档位 | 抽样 | 相似帧复用阈值 | 画面索引耗时¹ | 无台词高光 |
|---|---|---|---|---|
| 极速 | 只看台词附近，40 点 | 0.60（大量复用） | ~10 秒 | ❌ 会丢 |
| **平衡**（默认） | 全片每 12 秒，100 点 | 0.85 | ~1 分钟 | ✅ 保留 |
| 质量 | 全片每 8 秒，150 点 | 0.93 | ~3 分钟 | ✅ 更密 |
| 极致 | 全片每 5 秒，239 点 | 0.97 + 动作权重加倍 | ~8 分钟 | ✅ 抓得最狠 |

¹ 20 分钟素材、RTX 3060 实测。整条流水线还要加配音约 7 分钟（恒定地板）与合成约 1 分钟。

配套机制：解说词里的**动作词会被归一**（接吻 / 热吻 / 相拥 → 同一个「吻」），命中时加权。中文 bigram 对同义动作本来看不见——「接吻」与「吻在一起」共享 0 个 bigram，不做归一就永远配不上。

### 直播切片

把一场直播录像（OBS 录制 / 平台回放下载）自动找出高光时刻，在**精剪时间轴工作台**上自由调整后出片。

**四路信号找高光**：音量能量 + 画面运动 + 台词密度/高能词 + **弹幕热度**（可上传 B 站弹幕 XML——观众用弹幕投票「哪里好看」，权重最高），全部按全片分位次相对评分（整场安静或整场喧闹都不会误判），每段附「为什么入选」的可读理由。

| 能力 | 说明 |
|---|---|
| **精剪时间轴工作台** | 左侧 9:16 预览 / 右侧高能注释 / 下方序列时间轴+热度曲线；拖两端改起止、拖拽换序、分割、合并、删除，撤销栈 40 步 |
| **逐段音量** | 每段 0~200%，配「全部音量」滑条一键套用 |
| **候选试看** | 导出前每段可试看（播到段尾自动停），不盲改数字 |
| **输出画幅** | 竖屏 9:16（全景+虚化背景，发抖音推荐）/ 竖屏 9:16（居中裁切，**水平焦点可调**，防人脸截角）/ **横屏 16:9（1280×720 标准化）** / 原始横屏 |
| **自动封面 + 换封面** | 峰值附近智能选帧；不满意可指定时刻重抽，按导出画幅同步裁切 |
| **中文标题命名** | 按台词内容自动给每条切片起中文文件名 |
| **草稿恢复** | 历史记录里「↻ 恢复候选」，随时重进精剪工作台续调 |
| **分析可取消** | 长片分析随时可停；正式分析优先于后台预热，互不拖累 |
| **参数记忆** | 条数 / 时长 / 画幅 / 语言，下次开窗自动回填 |
| **长片护栏** | 90 分钟录像实测 4 分钟出全部候选；超过 90 分钟自动跳过台词信号再提速 |

保留原声不配音；理由诚实：改过边界的标「（边界已手动调整）」，自己圈的标「手动指定」。

### 其他

- **强卡点**：场景切换 / 大幅动作停顿帧匹对音乐鼓点，自动硬切 + 配乐
- **素材库与 B 站**：本地素材持久化；关键词搜片 → 下载 → 一键入库
- **自动封面**：智能选帧 + 大字标题，三种版式
- **GPU 编码**：自动探测 NVENC，不可用回退 libx264，三档画质
- **显存守门**：配音/写稿/看图按需换入换出；后台预热遇到正式任务自动让位——12GB 卡全程不打满
- **记录与清理**：生成历史带文案可搜索、可回改；输出目录保留策略（成片永不自动删）

```bash
git clone https://github.com/Yzm889/-Smart-video-highlights.git
cd -Smart-video-highlights
pip install -r requirements.txt
```

`torch` 请按 CUDA 版本单独装：

```bash
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu121
```

**启动**

```bash
# Windows：双击 启动视频工坊.bat
# macOS / Linux：
chmod +x start.sh && ./start.sh
# 通用：
python webui_server.py        # 然后打开 http://127.0.0.1:8765/
```

## 使用流程

### 一、做一条解说

1. 拖入片子（或从素材库 / B 站选）
2. 填**剧情**（不知道就点「🔎 一键查剧情」），或直接粘贴**你的稿子**
3. 有官方字幕就一并导入（GBK/UTF-16 也能直接拖进来）——会跳过 Whisper 识别，快很多
4. 点开始 → 进入**两步走**：
   - 第一步：生成全部配音，逐段试听（失败的段会标 ⚠ 并显示原因）
   - 第二步：确认后合成，出成片（合成前有确认框汇总段数与告警）
5. 想改就进**手动调整**：改文案、换画面、插 B-roll、调音量，再合成

### 二、做一条卡点

拖入图片 / 视频 + 选一首音乐 → 「⚡ 一键强卡点」→ 先出方案预览（可删切点、加切点、取消段落）→ 按调整合成。

### 三、切一场直播

1. 顶栏「直播切片」→ 选录像（OBS 录制 / 平台回放）或填本机完整路径；有 B 站弹幕 XML 一并选上（高光排序跟随观众热度）
2. 设条数与单条时长 → 点「① 分析高光」（长片分析可随时取消）
3. 进**精剪时间轴工作台**：拖两端调段长、分割 / 合并、逐段试看、逐段调音量
4. 点导出 → 确认框汇总段数与告警 → 出片自带封面与报告
5. 想反悔：历史记录里「↻ 恢复候选」随时重进工作台；封面不满意可指定时刻换

## 配置说明

配置写在 `ai_config.json`（已被 `.gitignore` 忽略，别提交）。参考 `ai_config.example.json`。

```json
{
  "local": { "enabled": true, "base_url": "http://localhost:11434/v1" },

  "vlm": {
    "enabled": true,
    "mode": "ollama",
    "base_url": "http://localhost:11434",
    "model": "minicpm-v4.5:latest"
  },

  "tts_local": { "engine": "auto", "rate": "+0%", "instruct": "" },

  "tts": { "provider": "", "base_url": "", "api_key": "", "model": "", "voice": "" }
}
```

| 段 | 作用 | 备注 |
|---|---|---|
| `local` | 本地写稿模型（Ollama） | Ollama 的 OpenAI 兼容端点在 `/v1` 上 |
| `vlm` | 看图模型 | Ollama **原生**端点在根上，`base_url` 不要带 `/v1`；旧配置写 `vision` 也认 |
| `tts_local` | 本地配音 | `engine: auto` = IndexTTS2 克隆；`rate` 正数更快；`instruct` 是音色描述 |
| `tts` | 云端配音（可选） | 填了 `api_key` + `model` 才走云端 |
| `video` | 编码策略 | `encoder`: `auto` / `cpu` / `gpu` |

> 不配任何 Key 也能全程出片——本地模型 + 本地配音默认就是完整链路。

## 模型与显存

12GB 显存（如 RTX 3060）实测可跑通全链路，推荐组合：

| 用途 | 模型 | 体积 | 说明 |
|---|---|---|---|
| 写稿 | `qwen3:8b` | ~5.0G | 14B 会和看图/配音抢显存，12GB 不建议 |
| 看图 | `minicpm-v4.5` | ~6.1G | 也可用 `qwen3-vl:8b`（~5.8G） |
| 台词 | faster-whisper | ~0.2G | 有官方字幕时完全跳过 |
| 配音 | IndexTTS2 | ~6.6G | 与写稿模型串行换入换出 |

三个模型不会同时驻留：管线按阶段释放显存（例如画面理解完成后立刻卸载 VLM，把卡让给写稿模型；后台预热遇到正式任务自动让位）。

## 中文字体

烧字幕和封面标题需要真正含中文字形的字体，探测顺序：

1. 环境变量 `SPRING_VIDEO_FONT`（字体文件绝对路径）
2. 项目自带 `assets/fonts/`（`.ttf` / `.otf` / `.ttc`）
3. 系统中文字体（Windows 雅黑 / macOS 苹方 / Linux Noto CJK）
4. 扫描系统字体目录

探测不到会**直接报错并给修复指引**，不会静默画出一片方块。

```bash
sudo apt-get install -y fonts-noto-cjk          # Debian / Ubuntu
sudo yum install -y google-noto-sans-cjk-fonts  # CentOS / RHEL
apk add --no-cache font-noto-cjk                # Alpine
```

> 商业发布建议用 OFL 协议的思源黑体（丢进 `assets/fonts/` 即可，无需改代码）。

## 常见问题

**配音听起来每句换一个人？**
默认引擎是 IndexTTS2 克隆，整片共用一条参考音。若在设置里显式选了 Qwen3-TTS，它按文字描述现场造音色，逐句调用就会每句不同——这是引擎特性，不是 bug。

**配音语速偏慢？**
`tts_local.rate` 调成 `+20%` 即可（保音高变速，不影响音色）。

**成片比原片短很多，正常吗？**
正常。解说覆盖到哪，画面留到哪；未被解说的镜头会被剪掉。这是剧情驱动剪辑的设计目标。

**稿子里引用的台词没换成原声？**
两个前提：引号前要有冒号或说话动词（`回了一句：`），且该台词必须在**片源时长内**。超出片源的引用会照常念稿，不会播不存在的画面。

**解说讲的是 A 的对话，画面放的是 B 的对话？**
多半是人名译名不一致（稿子写「柯蒂斯」、字幕写「科特」）。v1.4.53 起会自动归一；导入字幕时也有提醒。若仍遇到，检查稿子与字幕的人名写法是否一致。

**字幕拖进来乱码 / 没反应？**
v1.4.49 起 GBK / UTF-16 自动识别，官方字幕直接拖即可。旧版本请升级。

**直播切片提示「超过 90 分钟，跳过台词信号」？**
长片护栏：超过 90 分钟自动只用音量+画面+弹幕找高光（省一半时间）。想要台词辅助，启动前设环境变量 `LIVE_CLIP_ASR_MAX=99999`。

**直播切片选了横屏 16:9，出来的还是竖屏？**
v1.4.74 之前的版本有这个 bug（白名单漏了 hd）。升级到 v1.4.74+ 即可。

**显存不够 / 跑着突然变慢？**
先关掉其他占用显存的程序（尤其是常驻的 Ollama 模型）。配音与写稿模型是串行换入换出的，同时驻留会触发 WDDM 换页，表现为 GPU 占用高但利用率 0%。
