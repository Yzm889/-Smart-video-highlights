## 二、问题之间的关联与前置依赖

```
A1 片头未识别 ──────────────┐
   （解说起点错位）           │
                             ▼
                    B2 DP 候选变多选偏
                    ▲            │
B3 复用阈值太狠 ───┘            │
（动作被抹掉）                  │
                               ▼
                        动作镜头能否进候选池 ──► B4 动作词归一（已做）
                                                     │
                                                     ▼
                                          引用让位 / 具象句能否配对 ──► B5 误配风险
                                                     │
                                                     ▼
                                              B1 档位语义（用户如何选）
                                                     │
                                                     ▼
                                        A2 无 VLM 时的降级路径（需显式提示）
```

依赖要点：

1. **A1 应最先做**。它独立于其它问题，且不修的话，后面所有对齐优化都会被"前 5 句配片头"这一现象掩盖，看不出真实效果。
2. **B2 依赖 A1**：片头修好后，剩余句子的分布才正常，DP 的选偏问题才暴露得出来、可量化。
3. **B3 与 B4 是组合拳**：B3 决定"模型看没看到"，B4 决定"看到了能不能配对"。只做一个都不够。
4. **B1 依赖 B2/B3 的结论**：档位语义必须在知道"高档到底带来什么"之后再改文案，否则只是换一种误导。
5. **B5 依赖 B4**（动作词归一同时提升了引用匹配的可靠性），但它是独立可交付项。
6. **B6/B7/B9 不阻塞画质主线**，可与任何阶段并行。

## 三、总体改造思路

### 3.1 架构调整：从"一条流水线"到"三层可替换"

现状是一个长函数（`_narrate_by_plot`）串起抽样 → 描述 → 剧情理解 → 对齐 → 分配 → 配音 → 合成，任何一处的策略变化都要动同一坨代码。建议拆成三层，每层有明确输入输出、可单独测试与替换：

```
第一层  镜头库（Shot Library）
  输入：片源 + 档位
  产出：Shot[] = {start, end, 描述, 动作标签, 是否有对白, 是否片头, 场景 id}
  职责：只负责"看得全"（密度 + 复用阈值 + 字段集）
  关键：片头标记在这一层产生；档位只影响这一层

第二层  句子分型 + 对齐（Sentence Typing & Alignment）
  输入：解说稿（逐句）+ Shot[]
  产出：每句 {角色, 匹配镜头, 匹配分, 次优分差}
  职责：决定"这句要什么画面"
  关键：句子角色分类（钩子/具象/引用/留白/过渡）——
        钩子句与过渡句**不参与画面匹配**（它们本来就不描述具体画面），
        具象句才打分；这直接解决 B2，也让 A1 的影响降到最小

第三层  编排与合成（Orchestration）
  输入：句子分型结果 + Shot[] + 配音
  产出：成片
  职责：分配、字幕、原声混音、引用让位、留白
  关键：可观测——每句的匹配分与次优分差低于阈值时，UI 标记"这段可能对不上"，
        让人一眼看出哪里需要手改，而不是整片看着"差不多但说不清哪不对"
```

### 3.2 技术方案要点

| 主题 | 方案 | 取舍 |
|---|---|---|
| 片头识别 | 前 N 秒（默认 90s）内：① 无成句对白；② VLM 描述高度相似（相似度均值 > 0.95）；③ 描述含 logo/片头特征词 → 判为片头，正片起点 = 最后一个片头采样点之后 | 规则法零成本、可解释；漏判（网飞自制片头无 logo）用 ① 兜底 |
| 句子分型 | 用本地模型一次批量分类（37 句约 1 次调用，3–5 秒），输出角色标签 + 是否需要画面匹配 | 一次调用即可；也可先用规则（带引号=引用、含「（留白）」=留白、疑问/设问句=钩子），模型只兜底 |
| 对齐打分 | ① 排除非具象句；② 描述信息量惩罚（避免长描述吸走）；③ 动作词加权保留；④ 加入"同场景连续性"奖励 | 每项都有实测支撑才保留，不做玄学调参 |
| 档位语义 | 改为三问式命名：**覆盖档**（抽样密度）/ **识别档**（复用阈值）/ **精度档**（字段与帧宽）；或者保留四档但把文案改成"覆盖 vs 耗时"，并标注"平衡档对齐已达标" | 命名比参数更影响用户判断 |
| 可观测性 | 每句输出 {角色, 匹配分, 次优分差, 候选镜头数}；UI 在"手动调整"页显示低置信标记 | 让"哪里不对"可见，是把质量交回给人的关键 |
| 数据外置 | `%LOCALAPPDATA%\FrameCut\{webui_output,models,material_library,history.json}`，安装目录仅留程序；升级时程序替换、数据不动 | 解决 B7；需迁移旧数据（一次性脚本） |
| CI | flake8 扩到全仓（现在只查 `webui_server.py` + `tests/`）；增加「档位参数一致性」测试（UI 文案 vs `NARR_TIERS`） | 防文案与实现再次漂移 |
